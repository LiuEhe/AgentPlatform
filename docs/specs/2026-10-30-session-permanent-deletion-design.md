## 1. 背景与目标

当前助手支持创建、分页查看和切换会话，没有删除入口或删除 API。会话历史保存在 PostgreSQL，DOCX 原件和解析 Markdown 保存在附件根目录，草稿和已访问会话快照保存在前端页面内存。重复点击新建空白会话已有复用保护，但历史中的旧空白会话仍需用户主动删除。

目标是让用户通过一次明确确认，永久删除指定会话及其平台内关联内容；正常完成后刷新或重启均不能恢复该会话，也不会立即自动创建新的空会话。

首版包括单条删除、桌面及移动端入口、不可恢复确认、后端幂等接口、关联记录与附件清理、失败重试、前端缓存失效以及必要的恢复检查。

不包括批量删除、清空全部、回收站、撤销、定时删除、自动清空旧空白会话、单条消息或单个附件删除、用户体系改造、外部日志清理和磁盘安全擦除。

## 2. 方案比较与已选方向

| 方向 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 永久删除 | 直接清除会话及材料，不长期保留已删除正文 | 无撤销，必须明确确认并处理文件清理失败 | 用户已选择 |
| 可恢复删除 | 支持误删恢复 | 需要删除状态、恢复入口、保留期限与最终清理机制 | 不采用 |

永久删除的实现建议为：**数据库事务删除关联记录，附件由现有文件存储精确清理；用最小本地凭据记录尚未完成的清理。** 不新增表、不修改外键、不引入任务队列或清理框架。

仅删除数据库再尝试删除文件，会在中断后失去待清理目标；先删除文件则可能在数据库回滚后留下缺材料的可见会话。本地凭据用于避免这两种情况，不提供会话恢复功能。

## 3. 删除边界

| 内容 | 处理 |
| --- | --- |
| `chat_sessions` | 删除该会话行，包括标题和 continuation |
| `runs`、`messages` | 删除该会话全部历史运行和消息，包括失败及取消记录 |
| `message_files`、`agent_calls` | 删除该会话的附件引用和消息关联子调用结果，包括审核报告 |
| `files` | 删除该会话全部文件元数据，包括上传后尚未发送的文件 |
| 附件目录 | 删除配置根目录内、服务端确认的 `<agent_id>/<session_id>/`，包括原件、解析正文及该会话目录内的残留文件 |
| 当前页面内存 | 清除目标会话的消息、文件、草稿、附件选择、快照、失败重试目标及临时输出 |
| sessionStorage | 仅当指向被删会话时清除当前会话及客户端待确认消息指针 |
| agents、其他会话、共享制度知识库 | 保留 |
| 用户下载的文件、外部模型记录、Langfuse、备份 | 不在本功能删除范围内 |

永久删除指从应用的活动数据库与附件目录移除，不承诺覆盖磁盘介质、数据库 WAL 或既有备份。本轮不将删除扩展为外部系统的数据擦除。

## 4. 用户交互

### 4.1 入口与确认

- 每条会话提供可发现的删除操作，桌面与移动端语义一致，支持键盘访问，不以鼠标悬停作为唯一入口。
- 删除操作与打开会话是独立按钮，不嵌套按钮，点击删除不触发切换。
- 空白会话和有内容会话均须确认，不根据标题“新对话”推断它是否为空。
- 确认显示目标标题，说明“将永久删除此对话、消息和上传文件，无法恢复”；有本地未发送草稿时，同时说明草稿将被清除。
- 默认焦点放在取消操作；Esc、取消或关闭确认均不发出 DELETE 请求。标题作为文本渲染。
- 对话框的具体排版、图标及邻近样式由实施者依照现有设计 tokens 决定，不新增 UI 库。

### 4.2 忙碌与请求期间

- 上传、queued/running 或服务端执行仍在收尾的目标会话暂不能删除，提示先等待上传完成，或停止任务并等其结束。
- 删除不隐式取消任务，不在确认中提供“停止并删除”的组合动作。
- 后端始终校验忙碌状态；列表摘要缺少运行信息时，不为了展示按钮而逐条加载会话详情。
- 页面已有发送、上传、初始化或切换请求时，先禁止发起删除，避免未确认提交与删除交错；已在后台运行的其他会话不因此被取消。
- 删除请求期间，当前页面禁止重复删除、新建、切换、发送、上传与翻页；与目标无关的活动 SSE 可以继续接收。
- 删除在服务端被接纳后，关闭页面或中断客户端等待不撤回删除。用户重新进入可重试同一目标。

### 4.3 成功、部分完成与失败

- `204`：目标记录和附件清理均已完成，移除列表项与目标缓存。
- 已确认数据库删除、文件清理未完成：不再把会话作为可打开历史；清除其本地内容，显示“对话已删除，附件清理未完成”，提供针对同一 ID 的“重试清理”。这不是全部完成提示。
- `409`：保留会话和本地输入，展示忙碌说明。
- 网络失败或数据库提交结果未确认：保留重试目标，提示“删除结果尚未确认，请重试”；不得自动重新创建会话或重发旧消息。
- 用户主动再次确认同一未确认删除，或点击其重试按钮，不再要求重复的永久删除确认。新的删除目标仍需确认。
- 本地待确认目标只保存必要的会话 ID 与操作状态，不保存正文；可复用 sessionStorage 保存刷新后的清理重试目标，不将其作为服务端任务真源。

### 4.4 删除后导航与恢复

- 删除非当前会话：当前会话内容、草稿、附件选择和活动任务不变。
- 删除当前会话：清除当前状态，从服务端重新读取列表首屏并打开最近剩余会话；原有其他会话快照仍可恢复。
- 列表重新读取失败时，显示明确的加载错误和重试，不回退到已删快照，也不误认为列表为空。
- 无剩余会话：显示“暂无会话，点击新建对话开始”，输入和上传禁用，保留新建按钮。
- 初始化、刷新和 KeepAlive 激活时列表为空，均不自动调用创建接口。此规则也适用于首次进入；新建按钮是创建会话的入口，不在本轮引入发送时延迟建会话。
- 重新获取首屏后重置历史分页游标；不能仅因为当前加载页已删空就判定服务器无会话。
- GET 已保存会话指针返回明确的会话不存在时，清除失效指针和该会话快照，再按列表恢复或进入空态；普通网络错误不清除有效草稿。
- 其他标签页不做实时删除广播；在下次激活、读取或操作收到明确的会话 404 时，失效对应本地缓存。无法撤回已经展示在另一标签页中的内容。

## 5. HTTP 契约

新增 `DELETE /api/v1/sessions/{session_id}`，无请求正文，不依赖模型配置。

| 状态 | 错误码或响应 | 含义 |
| --- | --- | --- |
| 204 | 空响应，无 JSON | 指定会话删除及附件清理完成；合法 UUID 本来不存在且无待清理凭据时，同样返回 204 |
| 409 | `CONVERSATION_BUSY` | 目标仍在上传、执行或收尾，尚未实施任何删除 |
| 503 | `CONVERSATION_DELETE_INCOMPLETE` | 已确认数据库中无该会话，但附件或清理凭据尚未清理完成；重复 DELETE 继续清理 |
| 503 | `STORAGE_UNAVAILABLE` | 存储不可用或提交结果未确认，不表示已经完成删除 |
| 404 | `CONVERSATION_NOT_FOUND` | ID 格式非法，沿用当前 UUID 校验语义 |

错误沿用现有 `{error: {code, message, request_id}}` 结构；不返回内部路径、正文或 SQL 异常。前端 DELETE 客户端必须支持空响应，不能沿用成功后无条件 `response.json()` 的处理。

合法且不存在的 ID 不触发任意目录删除。只有数据库中确认的目标，或有效清理凭据所指向的目标，才能进入文件删除。

当前 CORS 仅允许 GET/POST/OPTIONS。实施时需要在现有允许方法中增加 DELETE；保持 origins、credentials、headers 及认证现状不变。此项是待审批的必要配置变更，本文不执行。

## 6. 后端职责与并发边界

删除用例由 `ConversationService` 协调；数据库事务归 `PostgresConversationStore`，目录和清理凭据归 `LocalFileStore`。Agent、图和通用 runtime 不参与删除。

复用现有会话 `operation(session_id)` 锁，将删除的检查、凭据、数据库提交和文件清理串行化。同会话 upload/submit 必须在同一入口锁下看到删除状态；数据库的会话行锁再次保证提交互斥。

忙碌判定同时覆盖 `_uploads`、持久 queued/running 以及目标运行尚未退出的本地执行任务；不能只检查 `active_run_id`，因为终态提交后执行任务可能仍在收尾。其他会话的锁、并发额度和请求不受影响。

删除事务锁定会话行，复核无活动运行，按外键顺序删除：

1. `message_files` 与 `agent_calls`（后者经目标会话的 messages 定位）。
2. `messages`。
3. `files`。
4. `runs`。
5. `chat_sessions`。

全部 SQL 在一个现有 asyncpg 写事务中完成；失败回滚，不新增级联外键。不在数据库事务中等待模型、文件系统线程或用户确认。

已接纳删除的执行句柄须纳入服务生命周期：客户端断开不导致释放锁后留下未等待的文件线程；服务关闭先收尾已接纳删除，再关闭存储。进程强制结束后的收尾由清理凭据覆盖。

SSE 不新增删除事件。首版不删除活动运行，目标已处于终态的订阅结束；后续新订阅返回会话不存在。前端使用会话 ID、请求代次和订阅版本忽略迟到事件，禁止把目标重新加入列表。

## 7. 数据库与附件的一致性

### 7.1 最小清理凭据

拟在配置的附件根目录下新增保留目录 `.deletions/`，由现有 `LocalFileStore` 管理，每个会话一个 `<session_id>.json`。

凭据只包含格式版本、服务端确定的 agent_id 和 session_id，不包含标题、正文、原文件名、任意客户端路径或恢复数据。写入必须使用同目录临时文件和原子替换，完成写入后才允许提交数据库删除。保证范围为进程崩溃后的恢复，不宣称抵抗磁盘损坏或断电丢写。

凭据是基础设施清理意图，不是软删除、回收站、业务表或可执行任务描述。只接受固定格式与项目允许的 Agent 标识，不执行凭据中的自由路径或命令。

### 7.2 正常时序

1. 获取目标会话操作锁，检查服务可写与目标忙碌状态；忙碌则返回 409，不写凭据。
2. 从数据库获取目标身份，验证附件目标目录和凭据路径边界，写入清理凭据；写入失败则不删数据库。
3. 执行第 6 节数据库删除事务。
4. 提交成功，或在提交响应丢失后通过新的数据库事务及同一会话锁确认会话已不存在，才允许清理附件。
5. 清理该会话的精确目录；目录或个别文件本来缺失视作已经清理，其他 IO 或边界错误不吞掉。
6. 删除凭据，返回 204。未完成第 5 或第 6 步则保留凭据，返回专用的部分完成错误。

没有附件也遵循同一时序；目录不存在无需创建目录。若第 3 步明确回滚，保留会话与附件，清除不再需要的凭据；清除凭据本身失败则记录 ID，恢复流程据数据库状态处理。

提交结果无法确认时，不删除附件、不报成功，保留凭据并返回 STORAGE_UNAVAILABLE。复核必须等待原写事务结束，不能凭客户端超时或一次旧快照判断提交失败。

### 7.3 重试与启动恢复

- 重复 DELETE 在相同会话锁下执行。会话仍存在则重新做忙碌检查与删除事务；会话不存在但有凭据则继续精确清理；两者均无则返回 204。
- 启动时，在取得既有数据库运行权并完成历史中断恢复后、接收业务请求前，枚举 `.deletions/` 内有效凭据并串行核对。
- 数据库确认会话不存在：清理目标目录并移除凭据。
- 数据库确认会话存在：表明此前删除未提交，保留全部会话与附件，只移除未提交删除的凭据；不自动再次删除用户会话。
- 数据库不可核实时不进行文件清理。单个目录清理失败或无效凭据只记录安全的标识和错误类型并保留待处理项，不阻止其他会话使用；既有数据库初始化失败行为不变。
- 恢复只消费删除凭据，不扫描整个附件库查找孤立文件，不启动常驻轮询或自动重试平台。未完成项在下次针对性重试或服务启动时再次处理。

### 7.4 文件安全与恢复界限

复用现有路径边界与 reparse point 防护，扩展到两层会话目录。删除前确认根目录、Agent、UUID 和整棵目标树安全；拒绝 symlink、junction、上级引用和越界目标，不扩大权限绕过失败。不得删除附件根、Agent 根、`.staging/`、其他会话或用户原始上传来源。

在已经提交永久删除后，程序没有会话恢复入口。附件清理失败只能重试清理，不能把备份文件自动还原成会话。运维备份恢复属于单独操作；若恢复旧备份，可能重新引入历史，不能宣称本功能负责清除所有备份副本。

## 9. 官方能力复用

- 数据库继续使用锁定的 asyncpg 0.32.0 连接池及 `Connection.transaction()`；本地源码位于 `backend/.venv/Lib/site-packages/asyncpg/connection.py`，现有仓储 `_connection(write=True)` 已封装事务。
- 路由复用锁定的 FastAPI 0.141.1 的 `APIRouter.delete()` 和空 `Response`；本地路由源码位于 `backend/.venv/Lib/site-packages/fastapi/routing.py`。沿用现有 AppError 响应。
- 并发与取消复用 Python 3.12/3.13 标准库 asyncio 和现有会话操作锁；文件操作复用 pathlib、json、os 与 shutil，保留项目路径安全策略。
- 凭据只补足数据库和本地文件之间缺少原子提交的业务缺口；不实现通用任务调度、事务框架或自动扫描器。
- 实施前仍须核对实际安装版本中采用 API 的源码与异常/取消行为；以上本地路径是本机核查位置，不能作为部署环境固定路径。

## 10. 验收标准

### 后端与存储

- 空会话、普通聊天、多轮聊天、失败/取消历史、含成功审核结果、仅上传未发送附件均可完整删除。
- 真实 PostgreSQL 测试证明目标关联行全部移除、其他会话及 agents 不变，事务中途失败全部回滚；无须更改现有外键。
- 文件测试证明只删除目标会话，已缺失文件可重试，越界路径、symlink/junction 被拒绝且其他目录未受损。
- 上传、queued/running、终态提交后的本地收尾均返回 409；与 upload/submit 同时发起时不存在删除后新增消息、材料或运行的情况。
- 凭据写入失败、SQL 回滚、提交响应丢失、数据库核实失败、文件部分失败、凭据移除失败均符合第 7 节；204 不存在未完成清理。
- 在“写凭据后、数据库提交后、部分文件删除后”分别模拟进程中断并重新实例化服务，验证恢复不会删除尚存会话的附件，也不会丢失已删会话的清理目标。
- 同 ID 连续/并发 DELETE 与响应丢失后的重试幂等；无模型配置也可删除。
- 客户端取消和服务关闭不泄漏操作锁、线程等待、执行句柄或额度；既有会话运行和 SSE 回归不受影响。
- 真实 ASGI 测试验证空 204、错误结构及既有允许来源的 DELETE 预检；不扩大来源或凭据策略。

### 前端

- 取消确认不发请求；快速重复点击只提交一次；删除按钮不会打开会话；键盘和移动端可完成操作。
- 删除非当前会话不丢失当前草稿、附件或正在接收的回答；删除当前会话后恢复最近剩余会话及其草稿。
- 删除最后一条、首次空库、刷新和 KeepAlive 激活均保持空态，不隐式新建；点击新建后输入和上传才可用。
- 分页已加载列表删空但服务端仍有历史时正确恢复最近会话，分页游标刷新后不重复或漏载。
- 普通失败、结果未确认与附件清理未完成有不同展示和重试行为；页面刷新可恢复必要的待确认删除 ID。
- 切换、加载更多、完成刷新、SSE 和旧错误重试的迟到结果不能重新插入被删会话；旧会话指针的 404 能恢复为空态或其他会话。
- 既有新建空白复用、幂等发送、草稿/附件隔离、取消和 SSE 回归继续通过。
