# 上下文管理

## 长期上下文

长期规则以仓库中的版本化文件为准：`AGENTS.md`、本目录的治理文档、当前 README 和已接受 ADR。关键架构事实与已批准决策不得只留在聊天记录、临时摘要或忽略的本地文件中。

代码或依赖变化使长期文档过时时，应在同一任务中指出并更新相关段落；如果更新涉及新的架构主张，先依照治理流程确认。规划材料必须明确标为规划，不得在摘要中改写成现状。

## 任务上下文

多步骤或跨会话任务应持久记录：

- 用户目标、范围与验收标准；
- 已检查的代码和文档；
- 实施计划及其状态；
- 已修改文件和关键实现决定；
- 已执行检查及结果；
- 未解决问题、风险和下一步。

优先使用已有任务/PR 记录承载进度。如果没有可用记录且工作确实跨会话，可创建与该任务直接相关的短说明；任务结束后不保留无用途的进度文件。任务记录不得复制整套长期规则，只引用对应治理文档。

## 会话恢复与摘要

恢复任务时先阅读 `AGENTS.md`、相关规则、任务记录和当前 Git 状态，再核对摘要中“已完成”的事项。摘要应保留原始约束、批准状态和未执行检查，不得把“建议”压缩成“已批准”，也不得把“未运行”总结为“通过”。

遇到摘要与仓库事实不一致时，以当前代码、版本化文档和用户明确决定为依据，并报告差异。重要决定发生变化时更新持久文档，避免依赖历史聊天恢复。
