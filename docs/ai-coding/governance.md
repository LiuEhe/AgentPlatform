# AI Coding 治理

## 目的与依据

本规则用于让 Codex 在 AgentPlatform 中持续遵守项目已有结构，并让新增约束可审查、可验证。本文件记录的现状依据仓库代码、锁文件、项目说明和配置；规则中标为“治理要求”的内容是本项目采用的执行约束，不表示相关自动化已经存在。

项目当前由 `backend/` Python 服务和 `frontend/` Vue 应用组成。仓库没有发现 CI 工作流、代码测试目录或 Agent 专用规则文件。根 `.gitignore` 当前不再忽略 `docs/`，因此本目录中的治理文档可纳入版本管理。

## 规则优先级与冲突处理

1. 平台和系统安全规则始终有效。
2. 用户当前明确提出的任务范围和约束优先于仓库内一般规则；用户未要求的范围扩展不能由 Agent 自行批准。
3. `AGENTS.md` 是本仓库的简明入口；本目录文档展开其中的治理要求。
4. ADR 记录特定技术决策。状态为“已接受”的 ADR 是当前决策依据；“提议”或“已废弃”的 ADR 不能描述为现行规则。
5. README、代码注释和历史计划可提供背景，但不能单独授权架构变更。规划材料不表示其内容已经实现或获准实施。

若新任务与已接受决策冲突，先列出冲突、涉及文件和可选路径，暂停冲突部分并等待用户决定。不要静默推翻旧决策；决定改变后更新相关 ADR 和受影响文档。

## 变更范围和架构审批

- 任务开始时明确需求、验收条件、预计修改范围及尚未确定事项。
- 新建文件前搜索现有实现和文档；新建模块应能说明现有模块为何不适合承载该职责。
- 新增仓库顶层目录、`backend/app/` 或 `frontend/src/` 一级模块、跨层抽象、框架或基础设施，以及改变已有模块公共契约，必须先向用户提交理由、影响和较小替代方案并获得确认。
- 普通需求所必需的局部文件可以在现有职责目录内新增；仍须遵循最小修改原则和项目现有命名方式。
- 额外改进和未来设想单独列为建议，不与当前任务捆绑实施。

## 技术决策记录

只为会影响后续实现、依赖、接口、安全边界或维护成本的重要决定编写 ADR。ADR 记录背景、决定、状态、日期和后果，并引用相关代码或文档。小型局部实现选择不需要 ADR。

## 规则维护

架构、依赖、接口、构建或安全机制发生变化时，检查本规则集和 README 是否需要同步更新。只改实际过时的段落，不为形式完整而重复抄录代码或建立空白文件。新增自动化时记录具体命令和执行入口；尚未接入的建议须标为“建议”。
