# 架构规则

本文规定代码应放在哪一层、各层如何依赖。当前目录与关键实现位置见[项目目录](project-structure.md)；功能、接口和操作步骤见各 README。

## 各层职责

| 位置 | 负责什么 | 不应放什么 |
| --- | --- | --- |
| `api/` | HTTP 输入输出、身份依赖，调用应用服务 | Agent 业务编排 |
| `services/` | 上传、执行、取消、删除、导出等应用用例；文件名 `*_service.py` | Agent 意图/路由、算法和存储实现 |
| `runtime/` | 通用注册、调用上下文与执行协议 | 具体 Agent 规则、HTTP 或会话存储 |
| `agents/<agent>/` | 专属图、状态、意图、参数、Prompt 和节点 | 对应用服务、账号或会话存储的反向依赖 |
| `nodes/` | 确有复用需求的公共处理能力 | 特定 Agent 的材料选择或审核策略 |
| `infrastructure/` | 供应商 SDK、数据库、文件与转换程序适配 | Agent 编排或 HTTP View |
| `schemas/` | 应用共享数据契约 | Agent 私有输入输出和图状态 |
| `core/`、`main.py` | 中立配置/错误/观测接口，以及资源装配注入 | 业务模块重复创建客户端 |
| 前端 `views/features/api` | 分别负责页面组合、业务交互、后端访问 | 后端 Agent 意图识别与业务编排 |

Agent 通过注入的能力访问外部系统或调用已注册 Agent。数据库目录记录只供展示，不授予执行能力；注册时不执行任务。

## 容易放错的内容

**记忆与历史。** Agent 的业务状态放在自己的 `graph/state.py`。短期消息、摘要和待补参数由官方 checkpointer 保存；完整消息、附件和运行记录由业务仓储保存；活动通知、临时文本、锁归进程内资源管理。不维护第二份完整历史快照或业务续接状态。

**文档与上下文。** 格式解析复用 `nodes/document/`；上传、保存、取消和额度由服务协调，避免重复解析。公共预算、裁剪、分片摘要及 Prompt 解析契约归 `nodes/llm/`；材料选择、任务模板、输出结构和动作校验归 Agent。

**数据库。** `infrastructure/database.py` 管理驱动、连接池、运行权和事务。身份与会话仓储通过 BaseDatabase 共享池；跨仓储授权和写入使用同一事务连接，业务 SQL 与拥有者判断仍归仓储。官方 AsyncPostgresSaver 是受限例外：由检查点适配管理独立 Psycopg 池，同库同 schema，只开放官方 API，不作为业务 SQL 旁路。

**文件与删除。** 基础设施负责读写和精确清理，服务协调数据库、检查点和文件。删除记忆使用共享 thread_id 与官方 `adelete_thread`，不放进 Agent 图或 runtime；数据库提交未确认时不盲删文件。

**资料与头像。** 账号摘要与完整资料分开。服务和身份仓储管理资料策略，管理员只读查看；头像验证与文件归身份基础设施，服务协调引用提交、精确清理和跨请求额度，API 只处理 HTTP 与接收量。不得混入会话附件、图状态或 Prompt。

**导出与追踪。** Word 转换独立于模型，不放入审核图或 runtime。中立观测接口归 core，SDK 归基础设施，评估规则归 Agent；追踪不替代历史，不改变业务结果，不自动收集用户文档作为数据集。

## 执行与数据一致性

- LangGraph 用节点与条件边表达流程。动态并行优先用官方 Send / Map-Reduce，明确 reducer 语义，按业务序号排序，汇总等待全部必要分支。
- 区分图内并发、同进程共享额度和跨进程额度；`max_concurrency` 不能替代共享限额。重试、流式事件与恢复优先复用对应版本的官方能力，不能把“采用框架”写成“已有持久恢复”。
- 模型、文档解析和 SSE 等待不持有长数据库事务。最终结果提交后才通知完成；订阅只读已有运行，断开不等于取消。
- 登录身份由服务端验证，会话和子对象按拥有者隔离，管理员不绕过归属检查。前端身份变化清理私有状态，认证 token 和 CSRF token 不写入 Web Storage。
- 记忆每轮只接收当前输入，从业务已提交 checkpoint_id 延续。成功归档与指针同事务提交，失败、取消、中断不推进。运行时只透传中立 resources，子 Agent 不自动继承材料 reader。
- 多个会话助手可共享 saver 和摘要机制，图状态、Prompt、策略各自独立。历史、检查点、附件和活动任务分别管理；历史持久化不等于任务可恢复，见[数据库说明](../database.md)。

## 变更前后

修改前查现有实现、实际调用方与锁定版本的官方能力，不为一次转发或未来假设加抽象。新增或迁移文件须列职责、输入输出、依赖和调用方。

新增顶层/一级模块、架构模式、基础设施或公共契约变更，按[治理流程](governance.md)先确认问题、方案、替代方案、影响与计划。实施后同步相关 README、架构说明和检查；现状与计划分开写，正式文档不依赖任务记录。

具体复用要求见 [AGENTS.md](../../AGENTS.md#官方能力与依赖复用)，检查要求见[质量门禁](quality-gates.md)。
