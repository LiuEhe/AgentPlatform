# AgentPlatform 前端

基于 Vue 3、TypeScript、Vue Router 和 Vite。正式界面采用暖白、炭灰与陶土色，交互图标统一使用已有的 `@lucide/vue`。所有会话、审核与导出操作调用现有后端接口，页面不包含演示回复。

## 页面与导航

- `/`：项目宣传首页，介绍平台价值，主操作进入智能体目录。
- `/agents`：智能体目录，提供会话助手和制度审核两个独立入口。
- `/agents/conversation-assistant`：独立聊天页面，左侧为会话记录；文件在输入框内预览、移除，发送后在对应消息中显示真实文件名。
- `/agents/institution-review`：独立制度审核工作台，支持草稿与标准 DOCX 对照或知识库审核，以及材料摘要、完整报告目录、复制和 Word 下载。
- `/agents/institution-review/flow`：制度审核静态流程结构，不表示实时执行进度。
- 未识别的智能体入口显示返回目录操作。

网站公共页面使用顶部“首页 / 智能体”导航。助手左栏只管理会话，移动端收进原生 `dialog` 抽屉；返回目录可选择其他智能体。

## 会话与文件

助手支持普通聊天、多轮追问、可选 DOCX 和粘贴正文。明确审核意图且参数齐全时，后端会话 Agent 可调用制度审核；普通问答不会被前端固定引向审核表单。

输入区 Enter 发送、Shift+Enter 换行；中文输入法候选确认不会发送。没有正文但附有文件时，以“请查看我上传的文件。”作为非空消息提交。文件成功被消息接收后清空本轮选择，历史消息保留附件；网络失败时保留输入与选择，响应丢失或 5xx 重试复用同一个客户端消息 ID。

新建不会删除已有会话记录，切回时恢复该会话的消息、未发送草稿和文件选择。Vue `KeepAlive` 保留助手页面内存；离开时中止客户端请求及 SSE 订阅，重新进入后读取会话并订阅同一活动任务，不取消服务端任务。切换期间禁止停止旧运行，迟到事件不会写入别的会话。用户停止仍调用取消接口，以返回结果或 SSE 的真实终态为准。

发送消息后使用浏览器原生 `EventSource` 订阅 `/api/v1/conversations/{id}/runs/{run_id}/events`，没有定时轮询。普通对话逐步追加真实模型文本，制度审核只显示真实执行阶段与完整报告。`snapshot` 替换临时回答，`delta` 追加，`state` 更新阶段，`done` 用正式消息替换临时文本并关闭连接。临时文本也经过现有 Markdown 与 DOMPurify 渲染，失败或取消不保留为成功回答。

断线由原生 EventSource 按服务端给出的 3 秒间隔重连；连续三次错误或永久连接错误后关闭，执行一次 JSON 状态查询以识别任务终态/会话失效，再提示手动重试连接。重试只订阅同一任务，不重新提交消息。重连首先接收累计文本快照，不重复追加旧文字；该恢复仅限当前进程的有效临时会话。

消息、文件名、标题和草稿只保留在当前浏览器页面内存。现有 `sessionStorage` 只存当前会话/客户端消息 ID，不持久化正文；刷新会尝试恢复当前有效会话，不保证恢复完整记录列表。后端过期或重启后材料与会话失效，不提供长期历史。

## 制度审核与报告

工作台初始选择标准文档方式，草稿与标准都齐全后可提交；切换知识库方式会清空标准文件选择。支持文件选择和拖放，前端检查 DOCX 扩展名与空内容，后端负责真实解析和容量限制。提交期间禁用文件及方式更改。

`POST /api/v1/reviews` 使用 FormData 字段 `file`、`review_mode`；标准模式增加 `standard_file`。该请求同步返回完整 Markdown。后端的缺省方式仍为 `knowledge_base`，前端始终显式提交所选方式，公共契约未变。

“停止等待”只中止当前客户端请求并忽略迟到结果，不撤回服务端已提交的审核；材料仍保留，重新提交从头执行。离开审核页面同样中止客户端等待。

报告使用 marked 官方 Renderer 生成稳定且不重复的章节定位，再经 DOMPurify 清理 HTML；不从正文推断风险数量，不删除合法内容。复制操作使用完整原始 Markdown，剪贴板不可用时提供手动复制文本。Word 下载独立调用 `POST /api/v1/documents/export/docx`，失败保留报告并可单独重试，不重新审核。切换报告或离开页面会取消未完成的导出请求。

流程结构仍使用现有 graph API、节点和连线，不显示审核百分比、剩余时间或节点级运行进度。

## 本地运行与检查

需要 Node.js 20.19+ 或 22.12+、pnpm。首次准备环境按项目锁文件安装；已安装环境直接启动：

```powershell
pnpm dev
```

Vite 默认将 `/api` 代理到 `http://127.0.0.1:8000`。后端启动方法见 [后端说明](../backend/README.md)。若使用其他地址，在本地环境配置中设置 `VITE_API_BASE_URL`；模型和知识库凭据仅保存在后端。

开发者工具显示 `localhost:5173/api/...` 是代理入口，实际请求由 Vite 转发到后端。运行查询 HTTP 200 只表示查询成功，还须查看响应中的任务 `status` 和 `error.code`。例如 `CONVERSATION_INTENT_FAILED` 表示后端意图识别失败，应检查模型调用及网络；在受限沙箱中启动后端时，本地就绪检查可能通过而模型出网失败，应在获准联网的开发环境启动，无需将前端改为直连或修改 CORS。

```powershell
node --test src/features/conversation-assistant/useConversation.test.cjs
pnpm build
```

会话回归使用 Node 内置测试与已安装的 Vue/TypeScript，覆盖幂等重试、消息/草稿/附件隔离、切换失败恢复、停用请求、取消与切换竞态、每会话重试目标，以及 SSE 增量、重连快照替换、原生 EventSource 关闭与重连上限。没有新增测试框架或依赖。

## 代码职责

| 路径 | 职责 |
| --- | --- |
| `App.vue`、`style.css` | 公共外壳、KeepAlive、设计 tokens 与响应式布局 |
| `components/PlatformBrand.vue` | 公共页和助手侧栏实际共享的品牌入口 |
| `views/` | 宣传页、目录、助手、审核及静态流程页面组合 |
| `features/conversation-assistant/` | 会话生命周期、内存记录、输入、消息内文件与执行结果 |
| `features/institution-review/` | 审核方式、草稿/标准选择、材料摘要与完整报告 |
| `api/` | 现有 HTTP 契约、错误映射与客户端中止 |

未引入全局状态管理库、数据库、认证或新业务 Agent。真实模型效果、文件解析、知识库与 Word/WPS 版式需在对应后端可用时另行验收。
